# Record a route outdoors

To draw a route without travelling there, choose Draw on map in the route editor. Enter decimal latitude and longitude in Go to latitude / Go to longitude, then press Go to coordinates (or Enter in either field). The map centres and zooms to that location, marked in orange. Click the map to place route points in order; the first becomes start/finish. Jumping to another location preserves existing route points and does not save or submit the route. Supported coordinates match the route API: latitude −85 to 85 and longitude −180 to 180.

As an administrator, open Routes → Create route → Record with GPS. Stand at the intended start/finish line and press Start GPS recording. Allow location access. Walk or run one complete loop in the direction competitors should follow, ending within 20 metres of the start. Stop recording → Use recorded route → review the map → enter the route name → Save route version. Choose that version when creating the room. A competition already created from another version keeps its original route.

The recorder follows your current position without drawing an artificial closing segment while recording. It accepts fixes with accuracy of 20 metres or better, samples no faster than every three seconds, and requires three metres of movement. It rejects stale fixes, implausible speed and distant reconnections after GPS gaps. It supports 4–500 route vertices and a minimum closed-loop length of 100 metres, consistent with the existing API. Near-duplicate finish vertices are removed before review to satisfy the backend's minimum two-metre vertex separation.

A single account-scoped GPS draft (coordinates, accuracy and timestamps) is saved in local browser storage after each accepted fix, including offline. Opening the recorder restores it. Closing the editor, switching drawing modes, or hiding the page stops GPS collection. Use Resume to continue near the last point. Switching accounts does not load another account's draft. Discard GPS draft explicitly removes the local draft; saved database routes and competition evidence are unaffected. Storage failure stops recording with a message; unsaved points remain in memory until the page closes. This draft is separate from the IndexedDB queue used for competition GPS evidence.

On a phone, use a deployed HTTPS address and keep the screen/app visible. The computer's `127.0.0.1` address is not reachable from a phone, and plain HTTP over a LAN does not provide the required secure geolocation context. Mobile GPS and background behavior still require outdoor device validation; a browser app does not guarantee locked-screen recording. Map tiles may be unavailable offline even though GPS draft capture continues.

## Lap display

Start the competition, then each participant opens its running screen and presses Start my run near the start/finish marker. Completed laps, current lap progress and the lap history are already displayed from database-backed API responses. The matcher requires direction, ordered checkpoints, at least 90% coverage, plausible speed and a finish-line crossing. Stationary movement and shortcuts do not earn laps. GPS batches upload every 15 seconds and the screen refreshes summaries every five seconds, so official counts are not instantaneous. Offline points are buffered and validated after synchronization. Route recording does not itself create competition laps.
